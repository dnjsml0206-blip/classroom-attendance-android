# 2026-10-14 잠금 완료 판정 정정 (0.9.23)

## 로그 재검토
09:04:48.273 전원 메뉴 시도 시 keyguard_locked=false/device_locked=false.
09:04:56.481 잠금 버튼은 발견되지 않았으나 keyguard_locked=true/device_locked=true.
09:05:02.577 화면은 켜져 있었지만 인증 잠금 상태는 유지됨.
따라서 '잠금 항목 탐색 실패'를 '휴대폰이 잠기지 않음'으로 해석하면 틀린다.
다만 기존 코드에 상단 자물쇠 드래그 구현은 없으므로, 어떤 동작/사용자/시스템 변화가 잠금을 유발했는지는 알 수 없다.
device_locked=true는 인증 잠금 관찰이며 강한 잠금 모드(생체인증 비활성화)까지 증명하지 않는다.

## 변경
- 시작 전 이미 인증 잠금이면 전원 메뉴를 열지 않는다.
- 메뉴를 읽는 중에도 앱 클릭 여부와 무관하게 인증 잠금 상태를 관찰하고 400ms 유지되면 종료한다.
- 전원 메뉴 시도 실패 시에도 이미 잠긴 상태이면 실패/대체 동작 대신 인증 잠금 관찰로 종료한다.
- 실패 후 아직 인증 잠금이 아니며 잠금화면이 표시된 경우에만 시스템 자물쇠 대체 동작을 시도한다.
- SystemUI의 lock_icon/lock_icon_view, 유효한 bounds, 활성/표시 상태, 접근성 ACTION_LONG_CLICK이 명확히 노출된 단일 대상만 사용한다.
- 실제 Samsung 자물쇠 접근성 ID/action은 현재 로그에 없어 이 경로는 실기기 검증 필요. 드래그 방향/좌표 추측은 구현하지 않음.
- 대체 동작은 한 번, 완료 대기 4초. 두 방법 실패 시 기존 화면 끄기 처리로 종료하며 재순환하지 않는다.
- 화면 끄기는 별도 결과이며 인증 잠금 성공과 혼동하지 않는다.
- lock_method/lock_icon_action_attempted와 각 동작 계획·수락·실제 잠금 관찰을 기록한다.
- 앞선 Wi-Fi 연결 직후 인증 유지 잠금화면 닫기 수정 포함.
