# 출석 사이트 연동 확인 결과

대상: https://skplanet.atosoft.net/Worknet/Present/Present.asp

## 확인한 내용 — 2026-09-10

공개 페이지와 해당 페이지가 참조하는 `present.js`를 읽기 전용으로 확인했다.
실제 사용자 인증값을 사용하거나 입실·퇴실을 변경하는 요청을 실행하지 않았다.

페이지는 기기에 저장된 `CstrCode`, `CstrCCode`, `CstrName` 쿠키를 사용한다.
본인 인증 링크의 발급 절차와 실제 계정의 인증 갱신은 미확인이다.
Android 앱은 자체 WebView에서 인증한 쿠키를 기기에 암호화해 저장한다.

## 페이지의 공개 코드에서 확인한 요청

아래 경로는 모두 같은 `/Worknet/Present/` 경로 아래에 있다.

| 경로 | 메서드 | 필드 | 용도 |
| --- | --- | --- | --- |
| Present.asp | GET | 없음 | 오늘 출결일과 페이지 구조 |
| PresentIP.asp | GET | strCCode | 교육기관 네트워크 허용 확인 |
| PresentPeriodChk.asp | GET | strCCode | 과정 진행 여부 확인 |
| PresentRollBookChk.asp | GET | strCCode, strCode | 오늘 입실·퇴실 기록 |
| PresentIn_ok.asp | GET | strCode, strCCode | 입실 변경 |
| PresentOut_ok.asp | GET | strCode, strCCode | 퇴실 변경 |

마지막 두 요청은 GET이어도 서버 상태를 변경한다. 일반 조회, 연결 진단 또는 CI에서 호출하지 않는다.

## 응답 판정

- 페이지의 ‘출결일’ 필드가 한국 날짜와 일치해야 한다.
- IP 및 과정 확인은 현재 구현에서 정확히 `1`일 때만 허용하고, `0`은 거부로 처리한다.
- 다른 플래그 값은 실제 응답 확인 전까지 알 수 없는 형식으로 처리한다.
- 출석 기록의 빈 응답 또는 `|`는 미입실 상태다. 이는 공개 페이지의 분기와 같다.
- `HH:mm[:ss]|`는 입실, `HH:mm[:ss]|HH:mm[:ss]`는 입실·퇴실 완료로 판정한다.
- 예상하지 않은 HTML, 시간, 필드 개수 및 입실 없이 퇴실만 있는 응답은 자동 처리하지 않는다.
- 변경 요청 응답 `0`은 사이트 거부로 취급한다.
- 변경 요청 후 반드시 오늘 기록을 재조회해 확인한다. 통신 실패나 기록 미확인은 재전송 보류 상태로 남긴다.

## 남은 현장 검증

- 앱 내부에서 본인 인증 링크를 사용할 수 있는지
- 실제 IP·기간·출석 기록 응답이 위 형식과 일치하는지
- 최초 인증, 만료 및 관리자 재등록 절차
- 허용 Wi-Fi에서 정상 입실·퇴실 후 서버 시각이 확인되는지
- 잠금 화면, 절전, 제조사 배터리 제한 아래 실행되는지
- 여러 과정 또는 특수 수업 일정에서 결과가 달라지는지

앱의 자동 처리는 기본적으로 꺼져 있다. 본인의 기록을 조회 모드로 확인한 뒤 사용자가 설정에서 켠다.

원본 쿠키, 인증 링크, 개인 식별값, HAR 및 인증된 HTML은 저장소에 포함하지 않는다.
