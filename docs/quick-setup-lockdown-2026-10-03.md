# v0.9.18 · 빠른 최초 설정 및 출결 후 잠금 진단

## 요청과 확인 범위

최초 자동출석 설정을 한 번 시작하면 필요한 항목만 안내하도록 줄인다. 출결 후 잠금 실패는 별도로 진단한다. GitHub `codex/device-logs` 최신 커밋은 2026-09-22 09:17 KST 업로드이며, 이번 잠금 실패의 새 로그는 아직 없다. 따라서 특정 갤럭시의 실제 실패 원인을 확정한 것으로 안내하지 않는다.

## 빠른 설정

설정과 연결 탭의 ‘빠른 설정’, 오늘 화면의 최초 설정 버튼에서 시작한다. ‘필요한 설정 자동 안내 시작’을 누르면 현재 허용 상태에 따라 완료 항목을 건너뛰고 다음 필요한 설정만 연다. 위치·알림 런타임 요청은 가능한 범위에서 한 흐름으로 묶고, 항상 허용·접근성·알람 등 필수 시스템 확인을 직접 마친 뒤 돌아오면 실제 상태를 재검사하고 다음 설정으로 진행한다.

거부·미완료 상태에서 시스템 화면을 반복해 띄우지 않는다. 위치와 알림을 함께 요청한 뒤 위치만 허용한 경우에도, 거부한 알림은 자동으로 재요청하지 않고 사용자가 ‘알림 허용하기’를 다시 눌렀을 때만 요청한다. Chrome 인증과 Extend Unlock은 열었다 돌아온 사실을 성공으로 간주하지 않고, 사용자의 명시적인 ‘직접 확인’을 남긴다. 이미 설정했다면 재방문 없이 직접 확인할 수 있다. 앱의 처리 방식 변경과 출석 예약 활성화도 별도 명시 버튼으로만 진행한다. 등록 Wi-Fi·시간·기존 설정을 임의로 초기화하지 않는다. 배터리 등의 권장 항목과 상세 5단계 가이드는 보조 버튼으로 제공한다.

Android의 권한 허용과 PIN 입력, 신뢰 장소 등록까지 앱이 대신 완료하는 것은 지원하지 않는다. 한 번 시작한 뒤 필요한 OS 확인만 하도록 이동 횟수를 줄인 방식이다.

## 잠금 처리 보완

- 기존 코드는 `getRootInActiveWindow()` 하나만 조회하고 4초 내 잠금 항목을 찾았다. OEM 전원 메뉴가 별도 시스템 창으로 노출되면 놓칠 수 있고, 기존 로그는 읽은 메뉴/후보를 남기지 않아 구분이 어려웠다.
- 시스템의 활성·포커스·시스템 창을 조회하고 활성 루트를 보조로 사용한다. 전원 끄기와 다시 시작이 함께 보이는 시스템 패키지의 전원 메뉴에서만 잠금 후보를 선택한다.
- 탐색 중에만 `FLAG_INCLUDE_NOT_IMPORTANT_VIEWS`와 필요한 창 조회 플래그를 추가한다. 종료·실패·취소 시 추가한 비트만 되돌리고 기존 이벤트 설정을 덮어쓰지 않는다.
- 중첩된 버튼·아이콘·라벨, 정확한 잠금 이름 뒤의 버튼 역할 접미사를 지원한다. 좌표나 부분 문자열만으로 누르지 않는다. 다른 동작이 섞인 부모, 여러 후보, 읽기 실패/생략된 트리는 클릭하지 않는다.
- 메뉴 탐색 최대 8초, 같은 대상이 600ms 안정된 뒤 한 번 클릭, 잠금 확인 최대 4초다. 재접속·출석 서버 요청은 추가하지 않는다.
- 로그는 시스템 창 수, 전원 메뉴 수, 잠금 라벨 수, 안전한 클릭 후보 수, 읽기 완료 여부, 클릭 전달, 인증 잠금 확인을 구분한다. 원문 화면 텍스트·PIN·계정은 저장하지 않는다. 최종 근거는 설정 환경에도 저장해 이후 업로드에서 확인 가능하게 한다.
- 설정에 구체적인 실패 이유와 화면 꺼짐 결과를 별도로 표시한다. 잠금 버튼을 못 찾고 일반 화면 끄기만 한 경우를 잠금 모드 성공으로 표시하지 않는다. 화면 끄기 설정 해제/기록 조회에 따른 생략도 기록한다.
- 실제 출결 없는 기존 ‘잠금 모드만 테스트’와 잠금 항목 표시 설정 도움말을 유지한다. PIN 요구 조건은 이전 사용자 승인과 같다.

## 실제 화면 검사

빠른 설정·상세 가이드 UI 검사 21개가 API 35 에뮬레이터에서 통과했다. 실제 출석 서버 요청 없이 설정 보존, 미완료 항목만 선택, Chrome/Extend의 명시 확인, 상세 가이드 복귀와 미완료 예약 차단을 확인했다. `build/quick-setup-2026-10-03/setup-checks.txt`에 결과를 보관한다. 빠른 설정·Extend 설명 화면의 겹침도 캡처로 확인했다.

첫 실제 시스템 잠금 검사에서 잠금 후보 1개를 읽고 단 한 번 클릭해 `LOCKDOWN_LOCK_OBSERVED`(인증 잠금)를 확인했다. 다만 화면 꺼짐의 기존 2.5초 확인 기간 동안 `isInteractive()`가 아직 true여서 실패로 기록됐고, 이후 시스템 전원 상태는 접근성 잠금 요청에 따른 Asleep을 보여줬다. 화면 끄기 요청을 추가로 반복하지 않고 관찰 기간을 최대 6초로 보완했다. 화면 꺼짐 결과에는 요청 후 경과시간도 기록한다. 이는 테스트 장치에서 확인한 지연이며 사용자 갤럭시의 실패 원인을 확정한 것은 아니다.

트리 조회가 느릴 때 조회 시작 시각부터 안정화 시간이 소모되는 문제도 확인했다. 이제 트리를 실제로 읽은 직후부터 동일 후보를 최소 600ms 관찰한 뒤 클릭한다.

재검사에서 실제 시스템 잠금 12개 검사가 모두 통과했다. 전원 메뉴를 한 번 요청하고 안전한 잠금 후보 한 개에 한 번만 클릭을 전달했다. 최초 메뉴 요청 후 1,713ms에 인증 잠금이 확인됐고, 이어진 화면 끄기 요청 후 131ms에 비대화형 화면 상태가 확인됐다. 전원 메뉴 읽기 근거는 `SYSTEM_WINDOWS`, 출석 페이지·입실/퇴실·확인 버튼 요청은 0회였다. 기록: `build/quick-setup-2026-10-03/lockdown-checks-final.txt`. 이는 API 35 에뮬레이터 검사이며 사용자 갤럭시의 실제 실패 원인은 최신 기기 로그로 추가 확인해야 한다.
