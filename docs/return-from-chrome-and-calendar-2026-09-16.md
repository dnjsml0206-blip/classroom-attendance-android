# Chrome에서 앱으로 복귀할 때의 대기와 달력 상태 선택

## 확인된 흐름

사용자는 Chrome이 열린 뒤 앱으로 돌아왔다고 정정했다. v0.9.3은 Chrome의 출결 주소를 처음 읽은 후 1.8초 동안 완료 시각도 읽지 않았다. 그 사이 앱으로 돌아오면 현재 창에서 Chrome을 읽을 수 없어 최대 70초의 클릭 전 복구 대기를 계속했다. 버튼은 busy 동안 비활성화되고, 확인된 시각이 없으면 표시하지 않았다.

이번 시도의 신규 기기 로그는 없으므로 기기에서 어느 단계까지 도달했는지는 확정할 수 없다. 9월 16일 09:08에 업로드된 기존 로그는 이번 설치 후 시험의 근거가 아니다. 아래 재현 검사는 이 흐름의 구현 문제를 확인한다.

## 변경

- 정확한 출결 주소와 오늘 날짜가 확인된 화면의 완료 시각은 즉시 읽는다. 새 출결 버튼 클릭 전의 1.8초 대기는 유지한다.
- Chrome 화면 이벤트를 짧게 묶어 읽되 연속 이벤트가 기존 읽기를 계속 뒤로 밀지 않게 한다. 별도 서버 요청은 없다.
- 출석 앱이 다시 활성화되면 남은 Chrome 대기를 종료한다. 미확인 시 해당 버튼 아래에 안내하고, 실제 시각으로 간주하지 않는다.
- 클릭 전 복귀는 자동 재시도만 2분 늦춘다. 수동 요청의 기존 3초 간격과 일일 제한은 유지한다. 클릭 후 복귀는 pending 및 자동 보류를 유지한다.
- 복귀 원인과 페이지를 읽은 뒤 경과 시간은 진단 버전 3에 기록한다. 페이지 원문이나 인증정보는 저장하지 않는다.
- 달력은 출석·조퇴·결석 중 하나를 누르면 즉시 저장하고 같은 버튼을 다시 누르면 해제한다. 시간 입력 및 저장 대화상자를 제거했다.
- 달력 시각은 Prefs.history의 확인된 기록만 사용한다. 기존 manual_times 값은 표시하지 않으며 상태 변경/해제 시 해당 날짜의 오래된 시간만 정리한다.

## 검증

- Java 단위 검사 101개, 로그 분석기 19개, 수동·예약 동작 24개, 달력 버튼·시간 출처 21개 통과.
- 실제 Android Chrome + 로컬 응답 재현 107개 통과: 일반 이미 입실 13개, 표시 준비된 입실 14개, 확인 전 복귀 19개, 클릭 후 복귀 16개, 일반 입실 13개, 퇴실 14개, 타 앱 가림 이후 복구 18개.
- 준비된 완료 화면은 페이지를 처음 읽은 뒤 3ms에 기록 확인, 일반 비동기 페이지는 이 실행에서 1137ms에 확인했다. 이는 에뮬레이터 측정이며 실제 서버·휴대폰의 로딩 시간 보장은 아니다.
- 복귀 시 1.5초 이내 작업 종료와 버튼 복구, 미확인 안내, 클릭 후 보류 유지, 클릭 전 자동 재시도 2분 지연 및 수동 3초 간격을 확인했다.
- 최종 APK를 다시 설치해 복귀 19개와 달력 21개 검사를 재확인했다. 화면 갱신 중 뷰가 잠시 없는 상태를 허용하도록 검사 코드의 조회를 보완했다.
- Android lint 오류 0개, 앱·검사 APK 빌드 성공, 기존 배포와 동일 서명 확인. 모든 재현 응답은 로컬에서 제공했으며 실제 출결 서버 요청은 하지 않았다.
- 미확인 시각은 새로 만들지 않고, 수기 시간 저장 기능에 해당하던 이전 단위 검사 5개는 기능 제거와 함께 삭제했다. 기존 시간값을 숨기고 실제 기록을 보존하는 검사는 달력 실기기 검사에 포함했다.
