# v0.2.0 구조

`enabled`는 미래 출석 예약의 사용 여부다. 감시 서비스가 계속 실행 중이라는 의미가 아니다.

1. AlarmScheduler는 수업 요일·휴강일과 확인된 오늘 기록을 이용해 다음 시작 또는 종료 경계의 정확한 알람을 예약한다.
2. AlarmReceiver와 ScheduleController는 현재 실행 구간을 판단한다. 구간 밖이거나 해당 출석 기록이 확인됐으면 MonitorService를 종료한다.
3. MonitorService는 입실 구간에서 위치·Wi-Fi를 감시한다. 퇴실 구간에서는 Wi-Fi 연결과 Chrome 처리를 확인하고 재시도 종료 시각을 지킨다.
4. AttendanceEngine은 등록 Wi-Fi에서만 ChromeAttendanceService에 확인을 요청한다.
5. ChromeAttendanceService는 Chrome의 정확한 출결 URL, 당일 출결일, 표시된 버튼을 확인한다. 자동 클릭 설정이 켜져 있을 때만 입실 또는 퇴실을 클릭한다.
6. 퇴실 확인창은 앞선 퇴실 클릭에 이어 나타나는 알려진 문구에만 응답한다. 결과는 화면에 표시된 입실시간·퇴실시간으로 확인한다.
7. 확인 기록은 기기의 날짜별 기록에 저장되고 감시는 종료된다. 다음 예약은 유지한다.

## 중단과 재시도

클릭 전에 날짜와 작업을 durable marker로 저장한다. 통신·UI 오류로 결과가 불명확하면 같은 작업을 자동으로 반복하지 않는다. 다음 조회에서 기록을 확인하거나 사용자가 실제 기록을 확인한 뒤 보류를 해제한다.

예약 시간이 끝나거나 출석 예약을 끄면 Chrome 확인 작업도 취소한다. 앱이 다른 웹사이트·다른 앱에 표시된 버튼을 출석 버튼으로 취급하지 않도록 Chrome 패키지, 주소, 날짜를 확인한다.

## 권한

예약 알람에서 위치 서비스를 시작하고 Wi-Fi 이름을 확인하려면 백그라운드 위치 권한이 필요하다. 예약 복구 수신기는 서비스 자체를 부팅 시 직접 시작하지 않고 알람을 복구한다.

접근성 서비스는 Android가 연결을 유지할 수 있다. 실행 중인 출석 요청이 없으면 내용 변경 이벤트를 요청하지 않고 주기 조회도 하지 않는다. 인텔리전트 Wi-Fi 탐색은 사용자가 버튼을 누른 뒤 15초 이내의 설정 메뉴 이동에만 사용한다.

기존 WebView 인증 및 직접 HTTP 출석 변경 코드는 제거했다. 앱은 Chrome 쿠키를 가져오거나 새로운 인증 세션을 만들지 않는다.
