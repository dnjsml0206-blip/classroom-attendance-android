# 예약 OFF/ON 및 오늘 화면 수정

## 원인

출석 예약을 켜면 ActivationRun이 5초 뒤 beginManual을 호출한다. 이 경로는 manualSession으로 실행된다. 예약을 끌 때 기존 ScheduleController.reconcile은 cancelScheduledWork만 호출했고, 이 함수는 예약 시간 밖에서도 수동 출결을 계속 확인하기 위해 manualSession을 보존한다. 그 결과 예약 OFF 뒤에도 busy 상태가 남았고 ON 버튼의 busy 검사에서 재활성화를 막았다.

## 수정

- 명시적으로 예약 OFF를 누르면 5초 대기와 현재 출결 작업을 함께 종료한다. 예약 시간 종료 등 일반 reconcile에서는 기존 수동 작업 보존 정책을 유지한다.
- 이미 클릭한 경우 저장된 날짜·단계·클릭 시각 및 접속 제한을 유지한다. OFF/ON 뒤 5초 실행은 이전 요청이 있으면 기록 조회만 수행한다. 임의의 재클릭은 하지 않는다.
- 현재 수동 작업 중에도 미래 출석 예약은 켤 수 있다. 진행 중인 작업과 경쟁하는 5초 실행은 추가하지 않는다.
- 사용자가 끈 사실은 ATTEMPT_CANCELLED / RESERVATION_OFF로 진단에 남긴다.
- 오늘 입실·퇴실 버튼 아래에 사이트에서 확인한 시각을 12sp 회색으로 표시한다. 수기 달력 값이나 이전 날짜의 시각을 완료 근거로 사용하지 않는다. 이미 확인된 입실을 누르면 Chrome을 다시 열지 않는다.
- Wi-Fi 상태를 오늘 제목 우상단의 작은 배지로 옮겼다. 낮·밤에 맞춰 연결은 녹색, 미연결은 살구색 계열로 구분하며 텍스트는 대기 중 / 와이파이 미연결을 유지한다. 하단 카드는 제거했다.
