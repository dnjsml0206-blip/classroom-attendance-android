# 잠금 상태 테스트 · 임시 메뉴

v0.8.0: 일반 예약은 설정의 **잠금 중 처리 방식**을 사용합니다. 임시 시험은 **Chrome 열기만 시험** 또는 **실제 입실·퇴실 시험**을 먼저 선택합니다. [일반 잠금 처리·진단](normal-unlock-v0.8.0.md)

v0.7.0부터 제작자용 앱의 설정 상단 **진단 · 제작자용 → 잠금 상태 테스트 열기**에서 사용합니다. 일반 배포용 앱에는 임시 테스트가 비활성화됩니다. 시험을 마치면 **테스트 완료 · 임시 메뉴 숨기기**로 예약과 테스트 알림을 정리하고 메뉴를 숨깁니다. 제작자 로그 업로드는 별도로 계속 사용할 수 있습니다. 이 메뉴의 선택은 평소 예약에 자동 적용되지 않습니다. 방법별로 한 번씩 비교한 뒤 맞는 방식을 선택하기 위한 실험 기능입니다.

## 실행 방법

1. 테스트 방법을 고릅니다.
2. 실행 목적에서 **Chrome 열기만 시험 · 출결 안 함** 또는 **실제 입실·퇴실 시험**을 명시적으로 선택합니다. 시험 진행 중에는 기존 예약 자동 클릭을 잠시 보류합니다.
3. **예약하고 화면 끄기**를 누른 뒤 전원 버튼으로 화면을 끕니다. 기본 15초이며 30초·60초로 바꿀 수 있습니다.
4. 자동으로 화면이 켜지는지 확인합니다. 시스템 인증 방식에서는 필요한 인증을 직접 완료합니다.
5. 메뉴로 돌아와 로그를 읽고 **성공 · 부분 성공 · 실패 기록**에 결과와 메모를 남깁니다.
6. **설정 → 진단 · 제작자용 → 로그 확인 · GitHub 업로드**에서 최근 최대 11개 시험 중 미업로드 기록과 일반 출결 동작 로그를 올립니다. 최초 연결과 미리보기 후 전송하고, 이 대화에 **로그 분석해줘**라고 알려 주세요. [연결 방법](github-log-upload.md)
7. **결과 전체 복사**로 전달하는 방법도 사용할 수 있습니다.

바로 비교하려면 **지금 테스트**를 사용할 수 있습니다. Chrome을 여는 테스트는 수동 열기·자동 출결과 함께 최소 3초 간격, 앱 전체 하루 20회 한도를 적용합니다. 실제 출결 시험은 일반 자동 출결의 입실/퇴실별 3회 한도도 공유합니다. 오류나 결과 미확인 시 해당 시간대의 자동 재접속이 중단됩니다. [접속 제한 기준](server-load-and-creator-tools.md) 화면이 이미 켜져 있는 상태의 성공은 화면 꺼짐/잠금 상태의 성공을 증명하지 않으므로, 예약 테스트와 비교하세요.

## 포함된 방법

방법을 고르면 앱에 **준비 → 실행 → 성공 확인**과 막혔을 때 확인할 내용이 바로 표시됩니다. **처음 한 번 확인할 설정** 버튼에서는 접근성·알람·알림 설정과 공통 시험 순서를 볼 수 있습니다.

| 방법 | 준비 | 실행과 성공 확인 |
|---|---|---|
| 화면 깨우기 | PIN·지문으로 한 번 해제 후 앱 복귀 | 예약하고 화면 끄기. 추가 터치 없이 Chrome이 열리면 성공. 잠금 화면에 멈추면 부분 성공 |
| Extend Unlock | 휴대폰 설정에서 신뢰 조건 한 가지 설정, PIN으로 한 번 해제 | 신뢰 조건 유지 후 예약. 추가 인증·터치 없이 Chrome이 열리면 성공 |
| 신뢰하는 Bluetooth 기기 | Extend Unlock에 워치 등 등록 후 실제 Bluetooth 연결 | 연결 유지 후 예약. 추가 인증·터치 없이 Chrome이 열리면 성공 |
| 신뢰하는 장소 | 위치 켜기, Extend Unlock에 현재 장소 등록, PIN으로 한 번 해제 | 장소에 머물며 예약. 추가 인증·터치 없이 Chrome이 열리면 성공. 앱의 30m 반경과 별도 |
| 신체 활동 감지 | Extend Unlock에서 감지 켜기, PIN으로 한 번 해제 | 예약 후 몸에 지니고 가볍게 움직이기. 추가 인증 없이 Chrome이 열리는지 확인. 책상 위에서는 60초 예약으로 비교 |
| PIN·지문 등 시스템 인증 | PIN·패턴 등 화면 잠금 설정 확인 | 예약 후 화면 끄기. 시스템 요청에 직접 인증하고 Chrome이 이어 열리면 성공. 이미 해제되어 인증 요청이 없었다면 다시 시험 |
| 잠금 유지 · 기기 연결 진단 | TACADEMY_5G 등 앱에 등록한 Wi-Fi 연결 | 예약 후 화면을 끄고 기다리기. 나중에 직접 열어 Wi-Fi 조건 확인 결과를 읽기. 서버 접속·Chrome 실행은 하지 않으며 서버 정상 여부나 인증·출결 성공을 뜻하지 않음 |

자동 동작을 확인할 때까지 알림이나 화면을 누르지 마세요. 시스템 인증 방식에서 요청한 인증은 직접 완료합니다. 반응이 없으면 예약 시각에서 최대 2분이 지난 뒤 앱에 돌아와 결과를 확인하고, 화면만 켜짐·인증 요청·알림 수동 진입 여부를 메모하세요.

보안 · Extend Unlock 설정 버튼은 휴대폰 보안 설정을 엽니다. 보안 또는 잠금화면 메뉴에서 Extend Unlock/Smart Lock을 선택하세요. 지원 항목과 경로는 제조사·OS에 따라 다릅니다. 앱은 신뢰 에이전트나 보안 설정을 자동으로 활성화하지 않습니다.

## 로그 읽는 법

- 예약 당시와 실행 당시의 **화면 켜짐/꺼짐, 잠금 화면 여부, 새 인증 필요 여부, 보안 잠금 설정 여부**를 기록합니다.
- **예약 요청에서 진입**은 호출 경로만 뜻합니다. 이전 버전의 **예약에서 자동 진입**도 자동 잠금 해제 성공을 뜻하지 않습니다. 예약 실행부터 화면 진입까지 지연(ms), 진입 시점의 잠금 상태와 사용자가 기록한 직접 조작 여부를 함께 확인하세요.
- **Chrome 실행 요청 전송**과 **Chrome 출결 주소 표시 확인**도 다릅니다. 후자는 접근성으로 실제 주소 표시를 읽었을 때만 기록합니다.
- Chrome 주소 확인은 사이트 인증이나 입실/퇴실 성공을 뜻하지 않습니다. 실제 출결은 기존처럼 사이트 기록으로 확인합니다.
- 앱은 어느 신뢰 방식이 활성화되어 잠금이 풀렸는지 확정할 수 없습니다. 선택한 조건과 사용자 확인 결과를 함께 비교하세요.
- 테스트 알람이 지연되거나 Android가 화면 시작을 제한하면 자동 진입이 확인되지 않을 수 있습니다. 확인 기한은 예약 시각부터 2분이며, 오래된 알람·취소한 테스트는 실행하지 않습니다. 앱 복귀 시 만료 결과를 정리합니다.

실제 입실·퇴실 시험을 선택해도 등록 Wi-Fi, 출석 예약, 수업일·입실/퇴실 시간, 완료 여부, 기존 Chrome 인증·접근성과 자동 클릭 설정을 적용합니다. 필수 조건이 빠지면 시험을 시작하지 않고 설정 경로를 안내합니다. 실행 중 조건이 바뀌면 원인을 기록하고 중단하며, 실제 출결 시험을 조회로 조용히 바꾸지 않습니다. 테스트 취소는 진행 중인 해당 테스트의 요청도 종료합니다.

## 서버 직접 처리 상태

잠금 유지 진단의 기존 HTTPS 확인 요청을 제거했습니다. 현재는 휴대폰의 Wi-Fi 조건과 전후 잠금 상태만 확인하며, 인증 페이지나 출석 서버에 접속하지 않습니다. Chrome 쿠키를 가져오지 않으며 실제 출석 변경 요청도 보내지 않습니다.

앱이 사용할 인증 방법과 출결 API가 제공되어야 잠금 상태에서의 실제 출결 처리를 추가할 수 있습니다. 현재 메뉴에는 이 준비 상태를 명확히 표시합니다.

## Android 공식 근거

- [KeyguardManager](https://developer.android.com/reference/android/app/KeyguardManager): 잠금 화면 표시와 인증 필요 상태는 구분됩니다. 신뢰 상태 또는 보안 잠금이 없는 경우 해제 요청이 바로 완료될 수 있고, 다른 경우에는 시스템이 인증 화면을 표시합니다.
- [Extend Unlock 안내](https://support.google.com/android/answer/9075927?hl=ko): 신뢰 기기·장소·신체 활동 감지와 유지 시간 제한이 있으며, 먼저 정상 잠금 해제가 필요합니다.
- [백그라운드 화면 실행 제한](https://developer.android.com/guide/components/activities/secure-bal): 화면 시작 요청을 보냈더라도 실제로 표시되지 않을 수 있어, 진입 여부와 알림을 통한 수동 진입을 별도로 기록합니다.

## v0.5.1 준비 상태와 오늘 퇴실 시험

상단 실행 준비에서 Chrome 접근성 연결, 위치 항상 허용, 출석 예약, 자동 클릭, 결과 알림과 Wi-Fi 확인 상태를 표시합니다. 접근성·예약 권한 등 필수 조건이 빠지면 시험을 시작하지 않으며 연결/출석 설정으로 이동할 수 있습니다. 조회 테스트는 입실·퇴실 버튼을 누르지 않습니다.

오늘 17:50에 Extend Unlock으로 시험하려면:

1. v0.5.1 APK로 업데이트하고 연결 탭에서 Chrome 접근성(연결됨), 위치 항상 허용, 정확한 알람, 결과 알림을 확인합니다.
2. 설정에서 출석 예약과 Chrome 자동 클릭을 켭니다. 퇴실 시간이 17:50인지, 오늘이 수업일인지 확인합니다.
3. 임시 메뉴에서 **Extend Unlock**과 **실제 입실·퇴실 시험**를 선택하고 **오늘 17:50:05 퇴실 테스트 예약**을 누릅니다. 버튼의 시각은 퇴실 설정을 따릅니다. APK 설치만으로 예약되지 않습니다.
4. 시험 직전에 TACADEMY_5G 등 등록 Wi-Fi에 연결하고, PIN·지문으로 한 번 해제한 뒤 신뢰 기기/장소 조건을 유지하면서 화면을 끕니다. 17:50부터 최대 2분 동안 휴대폰이나 알림을 누르지 않고 관찰합니다.
5. 끝나면 결과 기록에서 무조작/직접 화면 켬/직접 잠금 해제/알림 누름/시스템 인증 응답을 선택합니다. **로그 올리기 · GitHub**로 올려 분석합니다. 직접 조작해 정상 출석을 마무리했다면 그 사실도 기록합니다.

오늘 퇴실 예약은 한 번만 실행되고 다음 날 반복되지 않습니다. 예약 대기 중에는 기존 출석 감시를 보류하지 않습니다. 실행 시각부터 최대 2분 동안 테스트가 요청을 관리하며, 완료/취소/만료 후 기존 예약 흐름으로 돌아갑니다. 이미 퇴실 기록이 확인됐거나 휴강일이면 실제 출결 시험을 시작하지 않습니다. 앱 업데이트·재부팅 시 임시 테스트는 취소되므로 설치 후 예약해야 합니다.

Wi-Fi 연결 자체, 이름(SSID) 확인 가능 여부, 위치 항상 허용 여부를 각각 기록합니다. `SSID_UNAVAILABLE_BACKGROUND_PERMISSION`은 Wi-Fi는 감지됐지만 이름이 안 보이고 위치 항상 허용도 없는 상태입니다. 이 코드만으로 실제 연결이 끊겼다고 판단하지 않습니다. 이름·주소·사이트 본문·쿠키는 진단 로그에 추가하지 않습니다.

Chrome 실제 출결 시험은 주소 확인, 출결일/기록 읽기 대기, 버튼 발견 실패, 클릭 요청 결과, 확인 대화상자 클릭, 사이트 완료 기록을 구분합니다. 클릭 요청 전달만으로 출결 성공을 기록하지 않습니다.
