# v0.8.0 · 일반 예약 잠금 처리와 출석 진단 보완

일반 입실·퇴실 예약에서도 선택한 방식으로 화면 깨우기·시스템 잠금 해제를 요청하고, 자동 출석이 멈춘 단계를 로그로 구분하도록 개선했습니다.

- 설정에 **잠금 중 처리 방식**을 추가했습니다. 알림 후 직접 해제 / 화면 깨우기 / Extend Unlock·신뢰 상태 / 시스템 인증 요청 중 선택하며 저장 상태를 즉시 표시합니다. 기본값은 기존과 같은 알림 후 직접 해제입니다.
- 출석 시간·등록 Wi-Fi·자동 클릭 조건에서 입실·퇴실 각각 하루 한 번만 화면 깨우기를 시도합니다. 화면 표시가 제한되거나 인증이 필요하면 알림으로 안내합니다. PIN·지문은 사용자가 직접 인증합니다.
- 임시 시험은 **Chrome 열기만 시험 · 출결 안 함**과 **실제 입실·퇴실 시험**을 구분해 선택해야 실행됩니다. 일반 예약의 잠금 방식은 임시 시험을 숨겨도 유지합니다.
- 알람 예정·수신, 감시 시작 거절, 화면 포커스·인증, Chrome 주소·날짜·버튼 판독 실패를 기록합니다. 클릭 직전·클릭 접수·사이트 기록 확인을 구분하며, 보류 카드에는 날짜·입실/퇴실·저장 시각을 표시합니다.
- 서버 접속 제한과 중복 클릭 방지, 오늘 탭 출결 전용 표시, 기간별 로그 업로드 중복 제외는 유지합니다.

## 설치 후 설정

1. **classroom-attendance-0.8.0-creator-debug.apk**를 기존 앱 위에 업데이트 설치하세요. 앱을 삭제할 필요가 없습니다.
2. **설정 → 잠금 중 처리 방식 → Extend Unlock · 신뢰 상태**를 선택하고, 같은 카드의 바로가기에서 휴대폰 신뢰 설정을 확인하세요. 출석 예약·Chrome 자동 클릭·접근성 연결도 켜져 있어야 합니다.
3. 등록 Wi-Fi에서 설정한 출석 시간에 시험하세요. 화면 켜기 요청이나 인증 안내가 뜨면 직접 조작한 여부를 함께 기록해 주세요. ‘시스템 인증 요청’을 선택하면 Android 인증 화면에서 직접 인증합니다.
4. 시험 후 **설정 → 진단 · 제작자용 → 로그 확인 · GitHub 업로드**에서 로그를 올리세요.

화면 깨우기는 자동 성공을 보장하는 기능이 아닙니다. Android의 화면 표시·잠금 정책을 따르며 실제 휴대폰에서 확인이 필요합니다. 실패 시 반복해서 페이지를 열거나 버튼을 누르지 않습니다.
