## 17:50에 시작하지 않은 경위

9월 17일 14:04:30부터 퇴실 알람이 17:52:05로 등록됐고, 9월 18일과 21일 아침에도 같은 예약이 기록됐다. 9월 21일 17:51경에는 현재 설정이 17:50으로 바뀌고 감시 종료 경계가 18:00으로 등록됐다. 업로드 시점의 설정도 퇴실 17:50:05, 재시도 10분이다.

따라서 17:50에 운영체제가 알람을 놓쳤다고 판단할 근거는 없다. 17:51의 수동 실행 거절은 변경 전 17:52:05보다 이르다는 시간 조건에 걸렸을 가능성이 높다. 다만 구버전은 사유를 PREREQUISITE로만 기록하고 설정 저장 동작을 내보내지 않아, 변경 주체와 정확한 조건은 사용자 확인이 필요하다.

## 함께 업로드된 지난 기록

- 9월 17일·18일 퇴실 감시는 17:52:05에 시작했고 Wi-Fi 미연결로 대기했다. 해당 퇴실 Chrome 실행·클릭 기록은 없다.
- 9월 17일 09:31과 18일 09:06의 입실 완료 관찰에는 이 실행의 입실 버튼 클릭이 없다. 기존 사이트 시각을 읽은 결과이며 앱이 입실 버튼을 눌렀다고 세면 안 된다. 누가 먼저 처리했는지는 이 로그로 판별할 수 없다.
- 업로드 시점 Wi-Fi 미연결과 배터리 최적화 예외 꺼짐은 당시 상태다. 오늘 성공한 처리 시점의 Wi-Fi는 ALLOWED이며 이 업로드 상태를 과거 처리 실패 원인으로 대입하지 않는다.

## v0.9.6 보완

1. 직접 실행을 막은 이유를 CHECKOUT_NOT_OPEN, ENTRY_NOT_OPEN, NON_CLASS_DAY, Wi-Fi 사유 코드, ACCESSIBILITY_DISCONNECTED, OTHER_UI_WORK 등으로 구분한다. 검사 시점의 설정 시각·다음 알람·조회 전용 여부를 함께 기록하고 Wi-Fi 상태는 한 번만 읽는다.
2. 시간·요일을 실제 변경해 저장하면 SCHEDULE_CHANGED에 변경 전후 값과 다음 알람을 남긴다. 변경 없는 저장은 설정 변경 이벤트로 세지 않는다. 오늘 출석 기록에는 설정 내용을 추가하지 않는다.
3. 완료 기록에 AFTER_APP_CLICK 또는 OBSERVED_WITHOUT_APP_CLICK과 실제 사이트 날짜·입실·퇴실 시각을 남긴다. 클릭 없이 관찰한 기록을 사람의 수동 처리 또는 자동 클릭 성공으로 단정하지 않는다. 기존 기록 판정·클릭 횟수·서버 접근 제한은 유지한다.
4. 대기 중이던 설정 카드 도움말 대화창, 오늘 Wi-Fi 상태 터치 연결 보조를 함께 배포한다. Wi-Fi 자동 선택은 기기별 지원 범위가 다르며 [검증 범위](wifi-connect-from-today.md)를 따른다.

원본 로그는 Git 제외 경로 `build/log-analysis-2026-09-21/`에서만 보관하며, 이 보고서에는 계정·SSID·쿠키·화면 본문을 복사하지 않았다.
