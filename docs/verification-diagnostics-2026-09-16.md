# 화면·사이트 실패 진단 보강 — 2026-09-16

> 배포 후속: 아래 내용은 당시 로컬 검증 기록입니다. 이 변경은 이후 승인된 [v0.9.2 배포](releases/v0.9.2.md)에 포함됩니다.

Chrome이 열렸으나 출결 전에 화면 판독이 끊긴 경우를 다음 업로드에서 조사하기 위한 변경이다. 이전의 스탠드·달력·복구 수정도 유지한다. Git commit/push/release는 하지 않는다.

## 판단 원칙

- 현재 창이 Chrome이 아님 / 접근성 루트를 얻지 못함: 휴대폰 화면 접근 현상으로 기록한다. **사이트 차단 여부는 확인 불가**다. 포커스가 바뀐 이유나 OS/Chrome 내부 문제까지 확정하지 않는다.
- 현재 읽은 HTTPS 대상 사이트에 인증 필요·훈련 대상 아님·403/요청 제한/사람 확인·서버 오류·연결 오류 문구가 있음: 해당 **표시를 관찰했다**고 기록한다. 실제 HTTP 응답 코드, 요청 전송 여부, 자동화 차단 정책을 수집하거나 입증한 것이 아니다.
- 주소가 없거나 다른 사이트이면 페이지 문구를 대상 사이트의 거부로 분류하지 않는다. 모르는 문구·빈 화면·새 형식은 미확정으로 남긴다.
- 앱의 화면 판독/클릭 과정에서 RuntimeException이 발생하면 LOCAL_READ_ERROR 및 고정 오류 코드·작업 단계를 기록한다. 예외 원문은 저장하지 않는다.
- 버튼 클릭 접수, 서버 시간 관찰, 결과 불명확은 서로 다르다. 기존 중복 클릭 방지는 유지한다.

## 기록

CHROME_DIAGNOSTIC은 시도당 상태 변경 최대 14건, ATTEMPT_FAILED는 마지막 중단 시 별도 기록한다. 동일 attempt_id와 diagnostic_version=2로 기존 실행/클릭 이벤트와 연결한다. 실패 기록은 동기 저장한다.

1. 화면 켜짐, 키가드/기기 잠금, 현재/포커스 창 분류, Chrome 창 존재, 창 수.
2. 접근성 캐시 갱신 결과, 수집 노드/보이는 노드/WebView 수, 노드 수 상한 여부, 오류 코드와 발생 작업.
3. 주소 분류(출결/인증/같은 사이트/다른 주소/빈칸/미관찰), 알려진 사이트 문구 코드, 버튼 상태(클릭 가능/비활성/이름만 보임/없음/미관찰).
4. Wi-Fi 조건 코드, 클릭 시도/접수/퇴실 확인 시도/저장된 보류 여부, 경과 시간, 판독 횟수, 마지막 Chrome 이벤트 이후 시간.
5. 마지막으로 읽은 사이트 주소 분류·문구 코드와 그 관찰 이후 시간. **이전 관찰을 현재 화면의 증거로 재사용하지 않는다.**

이름, 페이지 원문, 전체 URL/쿼리, 인증 정보, 쿠키, 실제 SSID, 다른 앱의 이름·내용은 이 진단에 저장하지 않는다. 스크린샷도 자동 수집하지 않는다.

기존 ‘로그 올리기’에 자동 포함된다. 최근 7일/최대 200건에 더해 진단 이벤트의 출력 크기를 약 120 KiB로 제한하여 기존 256 KiB 업로드 제한에 여유를 둔다. 한도를 넘으면 오래된 이벤트부터 제외한다. 상세 진단을 별도로 켜는 설정은 필요 없다. ‘오늘’ 출결 로그에는 이 진단 이벤트를 추가하지 않는다.

## 동작 범위

이 변경은 현재 Android 화면을 읽고 기록하는 기능이다. 진단용 사이트 접속·HTTP 요청·새로고침·재클릭을 추가하지 않는다. Chrome 내부 HTTP/쿠키나 서버 DB 상태를 직접 조회하지 않는다. 화면 자체를 읽지 못하면 사이트 차단 여부는 여전히 확정할 수 없으며, 그 구분 불가 상태를 명시한다.

- Java 단위 검사 106개 및 Python 분석기 검사 19개 통과.
- 실제 Android 15 / Chrome 124 로컬 재현 8개 시나리오, 합계 119개 검사 통과.

원본 형태의 동적 인증 오류 화면에서는 화면에 그려진 문구가 접근성 노드에 빠지는 경우를 관찰했다. 이 경우 PAGE_FORMAT_UNVERIFIED/NONE_RECOGNIZED로 남겼다. 문구를 읽을 수 있는 대조군에서는 SITE_AUTH_MESSAGE_SHOWN/AUTH_REQUIRED로 구분했다. 같은 원본 인증 화면도 재실행 중에는 문구를 읽은 경우가 있었다. 따라서 Chrome이 열렸다는 사실이나 오류 문구 미관찰을 사이트 차단/정상 근거로 쓰지 않는다.

구분을 검증하는 초기 검사에서 위 접근성 누락과 즉시 실패 시 중간 이벤트가 없는 경로에 대한 시험 가정을 바로잡았다. 최종 검사에서는 이를 각각 미확정과 최종 진단으로 검증했다. 앱의 진단 코드를 시험에 맞춰 강제로 인증 실패로 분류하지 않았다.

8개 시험의 앱 이벤트·로컬 요청 기록과 자동 생성 분석은 build/diagnostic-evidence-2026-09-16에 보관했다. 최신 실패 뒤의 승인 없는 재클릭은 없으며, 실제 Galaxy/학교 서버 동작은 업데이트 설치 후 시험이 필요하다.
