## v0.9.19 변경

- v0.9.18의 별도 시스템 창 판독·정확한 잠금 후보 선택·잠금 실패 단계별 기록을 포함한다. 사용자가 준 5개 항목(전원 끄기, 다시 시작, 긴급전화, 잠금 모드, 의료정보)과 측면 버튼 설정을 순수 선택 정책의 회귀 입력으로 추가했다. 이는 실제 갤럭시 접근성 트리를 확보한 시험은 아니다.
- 신뢰 모드에서 화면이 깨어난 직후 인증 잠금이면 최대 8초만 로컬 상태를 관찰한다. 그 안에 신뢰 상태가 확인되면 즉시 Android 잠금 해제 요청으로 이어간다. 8초 뒤에도 인증 잠금이면 종료한다. PIN·지문을 입력하거나 신뢰 설정을 바꾸지 않는다.
- 출석 시간의 기존 감시 서비스에서만 `ACTION_USER_PRESENT`를 수신한다. SystemUI는 system UID와 다른 특권 UID를 사용하므로 이 보호된 시스템 액션만 필터링하는 수신기에 `RECEIVER_EXPORTED`를 적용한다. 일반 앱이 이 보호된 액션을 발송할 수 없으며, 수신 후에도 실제 잠금·네트워크·시간 조건을 다시 확인한다. 실제 Wi-Fi·화면·잠금 상태를 재검사해 즉시 이어가며, 완료·시간대 종료 시 수신기를 해제한다.
- Wi-Fi가 새로 준비된 경우와 실제 잠금 해제 시 로컬 60초 확인 대기만 건너뛴다. `TrafficGuard`의 최소 3초 간격, 자동 3회/시간대, 일일 20회 및 결과 미확인 보류는 그대로 적용한다. 연결·잠금 상태 확인 자체에는 출석 서버 요청을 추가하지 않는다.
- 깨우기 이벤트에 화면 켜짐·화면 잠금·인증 잠금·경과시간을 함께 기록한다. 신뢰 대기와 사용자 해제 수신을 구분한다.

## 잠금 유지의 범위

전원+볼륨 버튼을 물리적으로 누르는 대신 Android 접근성의 전원 메뉴 열기를 사용하고, 시스템 창에서 정확히 확인한 잠금 모드를 한 번 클릭한다. 이후 앱은 다음 예약까지 깨우기나 잠금 해제를 시도하지 않는다. 사용자가 직접 해제한 휴대폰을 계속 재잠그는 감시는 추가하지 않았다.

잠금 모드는 사용자 인증 전까지 유지되며 시간 예약으로 풀 수 없다. 다음 출석 전에 인증을 한 번도 하지 않으면 Chrome 자동 출결도 진행할 수 없다. 상단 열린 자물쇠 사진만으로 실제 접근성 이름·클릭 동작을 확인할 수 없어 좌표 클릭 또는 미검증 아이콘 클릭은 추가하지 않았다. 사진의 전원 메뉴 잠금 모드를 우선한다.

근거: [Google의 Extend Unlock 및 수동 잠금 안내](https://support.google.com/android/answer/9075927?hl=ko).
